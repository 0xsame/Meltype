# 報告された誤変換のコーパス

GitHub の issue（open / closed の両方）から、「打ったもの (キーをそのまま)」と「期待した結果」を取り出したものです。
判定を変えるときに、同じ物差しで比べるために使います。

## 使い方

```bash
dotnet run --project src/Meltype.Core.Tests -c Release -- --expect src/Meltype.Core.Tests/data/issue-cases.tsv /tmp/issue.json
```

標準出力は空で、結果は出力 JSON に書かれます（79 要素の配列。要素は `typed`・`expected`・`kind`・`actual`・`ok`）。

## 集め方（この順に絞る）

1. 全 issue 633 件のうち、「打ったもの (キーをそのまま)」と「期待した結果」が両方あるもの: **174 件**
2. 入力が「英数字・空白・`.,'_/-`」以外を含む: **21 件**を除く（日本語を含む 11・backtick を含む 8・その他 2）→ 153 件
3. 期待に漢字を含む: **41 件**を除く → 112 件
4. 期待が「かな・カタカナ・英数字・空白」以外を含む: **31 件**を除く（backtick を含む 21・`.` `-` `/` を含む 10）→ 81 件
5. 同じ組: **2 件**を除く → **79 件**

## いまの結果（main `b6f23b3` 時点）

| 条件 | 結果 |
|---|---|
| `--expect` | **61/79** |
| アプリと同じく同梱の語句 (`phrases.txt`) を読む `--henkan` で 1 件ずつ流した場合 | **62/79**（差は `todorisuto` の 1 件） |

## 注意

- **`--expect` は同梱の語句 (`phrases.txt`) を読みません**（`Keyboard` を `userDictionary` なしで作るため）。`phrases.txt` を変える変更は、このコーパスの点数を動かしません。アプリと同じ条件で見たいときは `--henkan` を使ってください
- **`--expect` は最後に必ず Enter を打ちます**。報告の「最後に押したキー」は見ていません（Enter 以外が 39 件）。入力途中の表示を確かめるコーパスではありません
- 期待に backtick などを含む 21 件は対象外にしています。backtick を外すと 20 件は通ります
- **報告どおりの期待が、その後の判断で見送り・変更になっているもの**があります。物差しとして数えるときは除いてください
  - `dlsite → dlして`（#886: サイト名の DLsite と両立させるため、いまは `dlsite` のまま）
  - `data → data`（#602: 見送り）
  - `url → URL`（#253: 大小文字だけの差。報告は shift で打ったときの話で、記録された入力は小文字 `url`）
  - `isyu- → issues`（#296: 報告の「最後に押したキー」が選択肢にない値）
  - `jstohtml → jsとhtml`（#1165: 本文の不具合は「js⏎と⏎html で html が消える」で、単発入力の期待とは操作が違う）
- このファイルは **2 列（入力・期待）だけ**です。`--expect` は 3 列以上の行を黙って捨てるので、出典の列は足せません（issue 番号は持っていません）
- **CI には入っていません**（CI は `--eval` の比較のみ）。判定を変える PR では、手元でこのコマンドも流してください
- 自由記述の不具合・提案（633 − 174 = 459 件。うち `誤判定` ラベル付きで欄が欠けている 6 件を含む）は、打ったものと期待が分かれて書かれていないため自動では取り出せません。必要になったら、その報告を読んで手で足してください
